# 근거 보강 1: 고정 감점을 구조로 바꿔도 결과가 같은가

> 생성: 2026-11-03 · `node scripts/penalty-structure.mjs --seeds 5 --evals 200000` · 182초
> 생성기 동작은 바꾸지 않았습니다. 같은 SA 해와 같은 난수로 비교 규칙만 바꿔 세 번 돌렸습니다.

## 질문
목적함수 J의 감점 **40**(평가 모델 정합성 규칙 위반, 무효)과 **15**(좁은 실·문 동선 문제 1건당)는 연구자가 정한 숫자입니다.
이 숫자를 "유효한 안이 무효한 안보다 항상 앞선다", "위반이 적은 안이 항상 앞선다"는 **우선순위(사전식 비교)**로 바꾸면 숫자 자체가 필요 없어집니다.
바꿔도 고른 평면이 같다면, 논문에서 40과 15를 "우선순위를 점수 하나로 구현한 것"으로 설명할 수 있습니다.

## 설정
| 항목 | 값 |
|---|---|
| 조건 | 20개(평형 59–114㎡, 방 2–4개, 선호 5가지 조합; `qubo-calibrate.mjs`와 같은 구성) |
| 시드 | 5개 → 실행 100회 |
| 풀이기 | SA, 평가 200,000회(시간 대신 평가 횟수로 고정해 재현 가능) |
| 후처리 | 템플릿마다 해 최대 4개 × 치수 다듬기 30회 (compare.js와 동일) |
| 가중치 | 보정 가중치 + 공간구문 대리 항(해당 선호를 고른 조건) |

| 규칙 | 비교 방식 |
|---|---|
| A 현행 | J = 기본점수 − 40·[무효] − 15·(위반 수) |
| B 무효만 구조 | 유효 여부 먼저 → 같으면 기본점수 − 15·(위반 수) |
| C 전부 구조 | 유효 여부 → 위반 수 → 기본점수 |

## 결과
| 지표 | 값 |
|---|---|
| A와 B가 같은 평면을 고름 | **100/100 (100.0%)** |
| A와 C가 같은 평면을 고름 | **99/100 (99.0%)** |
| 최종안이 무효 (A / B / C) | 0 / 0 / 0 |
| 최종안에 위반 있음 (A / B / C) | 20 / 20 / 20 |
| 최종안 위반 종류 (좁은 실만 / 문 동선만 / 둘 다) | 20 / 0 / 0 |
| 최종안 위반 비율 (평형·방 수별) | 59㎡ 방2 4/15, 59㎡ 방3 15/15, 74㎡ 방3 1/15, 84㎡ 방3 0/15, 84㎡ 방4 0/10, 101㎡ 방3 0/10, 101㎡ 방4 0/10, 114㎡ 방4 0/10 |
| 최종 후보가 모두 무효인 실행 | 0 |
| 채점한 안 전체 | 24,769개 (무효 0/24769 (0.0%), 위반 있음 16302/24769 (65.8%)) |
| 유효한 안의 기본점수 범위 | 36.82 – 91.53 |
| 최종 후보에서 (무효 최선 − 유효 최선) 기본점수 차의 최댓값 | — (40보다 작으면 40은 우선순위와 같게 작동) |

### A와 C가 다른 실행 (1회)
| 조건 | 시드 | A 위반·기본점수·모델 | C 위반·기본점수·모델 |
|---|---|---|---|
| 0 | 1 | 3 · 76.45 · 71.78 | 2 · 70.90 · 74.85 |

## 해석
- **감점 40**: 채점한 안 24,769개 가운데 무효가 0개입니다. 이 경로에서는 판상형 문법(buildLayout)이 정합성 규칙을 어기는 평면을 만들지 않으므로 40은 한 번도 작동하지 않습니다. 따라서 논문에서는 "무효 평면은 후보에서 제외한다(하드 제약)"로 서술할 수 있고 숫자 40은 필요 없습니다. 결과는 A와 B가 100/100 (100.0%) 같다는 것으로 확인됩니다.
- **감점 15**: 위반 수를 먼저 비교하는 우선순위(C)로 바꿔도 99/100 (99.0%) 같은 평면을 골랐습니다. 15는 사실상 "위반이 적은 안이 앞선다"는 우선순위로 작동합니다.
- **최종안에 남는 위반**: 모두 좁은 실이며 작은 평형(특히 59㎡ 방 3개)에 몰려 있습니다. C 규칙으로도 없어지지 않으므로 감점 크기의 문제가 아니라, 면적이 작아 최소 폭을 지킬 수 없는 조건의 문제입니다(별도 보고 필요).

## 한계
- 조건 20개는 QUBO 가중치 보정에 쓴 조건과 같습니다. 이 실험은 감점 구조만 비교하므로 보정 성능 주장에는 쓰지 않습니다.
- 생성기의 실제 시간 예산(300ms) 대신 평가 횟수로 고정했습니다. 풀이 결과의 질은 실제 화면과 다를 수 있습니다.
