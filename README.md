# 평면 평가 랩 (floorplan-eval)

AI 허브 아파트 평면도 샘플을 **정답지(기준 분포)** 로 삼아 도면을 채점하는 평가 모델과 Astro 웹 서비스입니다.
샘플 도면을 누르면 브라우저 안에서 평가 모델이 라벨 JSON을 분석해 점수를 냅니다.

2026-10-21 회의 결정을 반영했습니다.

| 회의 결정 | 반영 |
| --- | --- |
| PNG 대신 JSON 입력 | 모델 입력은 AI 허브 COCO 라벨 JSON. 원본 PNG는 화면 표시용으로만 씀 |
| AI 허브 데이터를 정답지로 | 지표마다 샘플 분포의 중앙값·강건 척도와 비교해 근접도 점수화 |
| 스페이스 신택스 기반 평가 | 실 인접 그래프의 깊이, RA·RRA, 통합도, 순환성 |
| 주관적 미적 평가 대신 시공 가능성 검증 | 정합성 규칙(필수 실, 도달성, 침실 비통과, 문·창 겹침, 개구부-벽 접합, 설비 짝) |
| 각자 평가 모델을 만들어 비교 | 모델 버전 관리, `npm run evaluate`로 같은 샘플에 대한 점수표 출력 |

- 저장소: https://github.com/hyeondata/drawing-library (이전 '도면 서재' 뷰어를 이 서비스로 교체)
- 배포 주소: https://drawing-library.kimyonghyeondata.workers.dev

## 실행

Node.js 24 이상이 필요합니다(`.nvmrc`).

```bash
npm ci
npm run dev          # http://127.0.0.1:8790
npm test             # 모델 테스트
npm run build        # 기준 분포 재생성 + 정적 사이트(dist/)
npm run preview
```

명령줄 채점:

```bash
npm run evaluate                        # 샘플 60건 점수표
npm run evaluate -- path/to/plan.json   # 생성한 도면 JSON 채점
npm run evaluate -- --json plan.json    # 상세 결과 JSON
```

## 예시 도면

`/examples/` 페이지에서 Sample 80장(공간·구조·설비·글자 각 20장)을 모두 볼 수 있습니다.
원본 PNG는 설비 12장뿐이라, 나머지 68장은 `scripts/build-drawings.mjs`가 라벨 좌표로 SVG(`public/drawings/`)를 그립니다.
도면을 누르면 확대·이동할 수 있는 뷰어가 열리고, 공간·구조·설비 도면은 바로 평가 화면으로 넘어갑니다. 색은 `src/model/drawing-style.js`에 있습니다.

화면의 **JSON 올려 평가** 버튼으로도 COCO 형식 도면 JSON을 바로 채점할 수 있습니다(SPA/STR/OBJ 자동 판별).

## 이미지로 평가

`/image/` 페이지에서 평면도 이미지(PNG·JPG·WebP)를 올려 평가할 수 있습니다. 이미지는 브라우저 안에서만 처리합니다.

1. **실 영역 찾기**: 어두운 선(벽·문·글자)을 찾고, 선으로 둘러싸인 빈 영역을 실 후보로 잡습니다. 실 이름 상자·가구처럼 한 실 안에 갇힌 조각은 그 실에 합칩니다(`src/image/segment.js`).
2. **실 이름 자동 인식**: 도면에 적힌 '침실 1', '주방/식당', '욕실2' 같은 글자를 브라우저 안에서 읽어(Tesseract.js 한국어, `src/image/ocr.js`) 그 글자가 있는 영역에 종류를 붙입니다. 오인식("혀과", "뇨레스룸")은 자모 단위 편집 거리로 실 이름 사전과 맞춥니다(`src/image/room-names.js`, 사전은 AI 허브 OCR 라벨 674개의 실 이름에서 만듦). 샘플 12장을 원본의 100·80·60·50·40%로 읽어 비교한 뒤, 80·60·50% 세 번을 합치도록 정했습니다. 영역을 찾지 못한 이름은 빨간 점선으로 표시하고, 그 위에 사각형을 그리면 종류가 자동으로 붙습니다. 한 영역에 이름이 여럿이면(트인 거실·주방) 나누라고 알립니다. 인식 파일(약 5MB)은 빌드 때 `public/ocr/`로 복사해 같은 사이트에서 받습니다.
3. **실 종류 고치기**: 영역을 눌러 실 종류를 고릅니다. 누른 지정이 자동 지정보다 우선합니다. 문이 그려지지 않아 두 실이 하나로 잡히면 **선 긋기**로 막고, 점선에 잘린 영역은 **합치기**, 타일·설비 선이 많아 찾지 못한 화장실·현관은 **사각형**으로 그립니다(변은 가까운 벽선에 붙습니다).
4. **평가**: 지정한 실을 AI 허브 SPA 라벨과 같은 COCO 형식으로 바꾸고(종이 가로 4963px 기준으로 좌표를 늘림) 같은 모델로 채점합니다. 라벨 JSON으로 내려받을 수도 있습니다.

한계: 영역 경계는 벽선 안쪽 선을 따르므로 사람이 그린 AI 허브 라벨과 조금 다르고, 열린 공간(거실·식당·복도)은 하나로 잡히기 쉽습니다. 글자 인식은 실 이름을 대부분 읽지만(샘플당 10~24개) 나무 무늬·타일 해치가 많은 도면은 영역을 찾지 못해 이름을 붙일 곳이 없을 수 있습니다.

## 평가 모델 (v0.3.0)

`src/model/`의 같은 코드가 브라우저, CLI, 테스트에서 돌아갑니다. 지표는 SCI/SCIE·SSCI 문헌 조사 두 번(지표 조사, SCI 투고 검토)을 근거로 골랐고, 지표별 근거·이유·한계는 [`evidence/`](evidence/README.md)에 정리했습니다.

| 종류 | 데이터 | 점수 구성 |
| --- | --- | --- |
| SPA 공간 | 실 폴리곤 | 공간구문(인접 그래프) 30 · 면적 구성 20 · 형태 10 · 외기 접면 10 · 정합성 30 |
| STR 구조 | 벽·문·창 폴리곤 | 라벨 정합성 60 · 구성 분포 40 |
| OBJ 설비 | 위생·주방 설비 상자 | 라벨 정합성 70 · 구성 분포 30 |

- **무엇을 재나**: '좋은 평면'이 아니라 **한국 실거주 평면의 거실 중심 유전형에 얼마나 부합하는가**와 **유효한 평면인가**입니다.
- **그래프**: 문 정보가 없어 벽을 맞댄 **인접 그래프**입니다. 덕트를 빼고 현관에 외부 노드를 붙여 통합도(1/RRA)를 계산합니다. 도면마다 축척이 달라(침실 한 변 160~487px) 침실 크기를 자로 삼아 길이·면적 기준값을 보정합니다.
- **채점**: 중앙값과 Qn 척도의 강건 z(이산 지표는 백분위), 방향이 정해진 지표는 단측, 평균 통합도는 실 수 보정 잔차. 평가 도면의 모든 세대는 기준에서 빼고, 같은 침실 수가 15세대 이상이면 그 층과만 비교합니다.
- **관문 규칙**: 필수 실 누락, 끊긴 실, 침실 통과 동선은 **유효하지 않은 평면**으로 따로 판정하고, 단일 점수로는 69점으로 묶습니다.
- **검증**: `npm run results`가 손상 실험·판별 타당도(`evidence/results/validation.md`)와 몬테카를로·부트스트랩·문턱값 민감도(`evidence/results/sensitivity.md`)를 다시 만듭니다. CI가 결과가 모델과 맞는지 검사합니다.

가중치, 기준값, 지표 목록, 근거 문헌(등재 상태 포함)은 모두 `src/model/config.js`에 있습니다.

## 한계

투고 전에 풀어야 할 일은 [`evidence/08-투고-검토-반영.md`](evidence/08-투고-검토-반영.md)에 우선순위로 정리했습니다.

- 공간 라벨에 문이 없어 링크가 출입이 아닌 인접 관계입니다. 손상 실험에서 통과형 침실을 잡지 못했습니다. 문 기반 그래프와의 일치도 검증이 필요합니다.
- 기준 분포가 20도면 35세대라 부트스트랩 점수 구간이 넓습니다(폭 중앙값 약 16점). 전체 AI 허브 SPA 9,095건으로 다시 만들어야 합니다.
- 축척을 알 수 없어 절대 면적·폭은 쓰지 않습니다. OCR 치수로 확정하면 면적대 층화를 할 수 있습니다.
- 샘플의 SPA·STR·OBJ는 서로 다른 도면이라 구조·설비 규칙은 라벨 정합성 점검으로만 씁니다.
- 전문가 선호·실거래가 같은 외부 기준 검증은 아직 없습니다.
- 근거로 정한 홍콩대 SCI 논문은 문헌 조사에서 찾지 못했습니다.

## 데이터 다시 준비

원본 `../Sample` 폴더가 있을 때만 실행합니다(Python 3 + Pillow 필요).

```bash
npm run data:prepare   # 라벨(OCR 포함) 복사, PNG → WebP
npm run baseline       # 기준 분포·목록 재생성
npm run drawings       # 예시 도면 SVG·목록 재생성
```

`public/`에는 화면용 데이터 약 2.4MB가 들어 있어, 저장소만 복제해도 바로 빌드할 수 있습니다.

## Git으로 평가 모델 관리하기

- `main`이 기준 브랜치입니다. 팀원은 각자 `model/<이름>-<내용>` 브랜치에서 평가 모델을 고치고 PR로 비교합니다.
- 모델을 바꾸면 다음 순서로 작업합니다.
  1. `config.js`의 `MODEL_VERSION`을 올립니다.
  2. `npm run check`(테스트 + 기준 분포 재생성)와 `npm run results`(검증 결과)를 실행합니다.
  3. 바뀐 `public/data/baseline.json`과 `evidence/results/`를 함께 커밋합니다.
- PR에는 `npm run evaluate` 점수표의 전후 차이를 붙여, 어떤 도면의 점수가 왜 바뀌었는지 보여 줍니다.
- 모델 버전마다 태그(`model-v0.3.0`)를 달면 논문에 쓴 점수를 그대로 재현할 수 있습니다.
- GitHub Actions(`.github/workflows/check.yml`)가 push와 PR마다 테스트, 기준 분포 최신 여부, 빌드, 배포 사전 검증(dry-run)을 확인하고 점수표를 실행 요약에 남깁니다.

## 배포 (Cloudflare Workers)

`main`에 push하면 Cloudflare Workers Builds가 `npm run build` → `npm run deploy`로 `drawing-library` Worker에 배포합니다(정적 자산, `wrangler.jsonc`).
수동 배포는 `npx wrangler login` 후 `npm run build && npm run deploy`입니다.
배포된 커밋은 페이지의 `<meta name="build-revision">`으로 확인합니다.

## 구성

```
src/model/       평가 모델 (config, geometry, labels, syntax, spa, str, obj, index)
src/pages/       Astro 페이지
src/scripts/     화면 동작(목록, 클릭 평가, 시각화)
src/styles/      스타일
scripts/         데이터 준비, 기준 분포 생성, CLI 채점
test/            모델 테스트
evidence/        지표별 근거 문서(논문·이유·타당성)
public/data/     라벨 JSON, baseline.json, catalog.json
```
